0. Task scope and ground rules

  • Review the initial testbench architecture found in the project (arcitecture/uvm_architecture_pro_updated.*), understand the DUT from RTL/databook, and propose an improved architecture only where technically justified.

1.4 Verification goal & methodology constraints driving the architecture

  • Goal: executable correctness of RV32I + M through the whole pipeline (top-level, core-as-a-whole). Simple exception scenarios limited to what misaligned/illegal paths exercise; ecall/ebreak not required.
  • Fact F1: Data/instruction memories are testbench components — we implement both as memory models inside the agents.
  • Fact F2: Instruction stimulus has two sanctioned options; we use pre-generated programs loaded into the instruction memory model — the core fetches naturally (see decision D2).
  • Fact F3: Checking philosophy: a small number of group-level checkers that ease debug — explicitly not one checker per RTL module.
  • Fact F4: No coverage points for features outside the goal (no FPU/CSR/IRQ/debug/sleep covergroups anywhere).

3. Review of the baseline — gaps and weaknesses

Verdict first: the baseline gets the shape right (pin-level UVM, slave agents on the two OBI ports, retire-level observation, reference-model compare, SVA by bind). The issues are missing definitions and a few responsibility/placement mistakes that would block or mislead implementation:

G1 — No test/top-level structure major
No uvm_test layer, no tb_top module, no stated owner of clock generation, no statement of where the DUT/interfaces are instantiated and how virtual interfaces reach config_db. Impact: first week of implementation stalls on conventions every test relies on.
G2 — The "RVFI Internal Interface" is a wish, not a design critical
The RTL has no RVFI port (verified: zero rvfi matches under rtl/). The baseline names a "RVFI Monitor (Internal State Monitor)" without defining which internal signals are sampled, how a retire event is detected, how flushed/killed instructions are excluded, or what the retire transaction contains. This component carries the whole checking strategy — it must be fully specified.
G3 — Duplicated/active-passive monitor split on the same pins major
"IF Agent (Active): Input Monitor" + "IF Agent (Passive): Output Monitor" on one interface (same for LSU) = two monitors observing the same signals, ambiguous ownership ("input/output" from whose perspective?), duplicated code, two analysis sockets for one transaction stream. One monitor per physical interface can observe both address and response phases.
G4 — Reference model responsibilities undefined critical
Since no external ISS is allowed, the RM is a hand-built RV32IM ISS in SystemVerilog. The baseline does not state its state (PC/GPRs/memory), what it consumes (fetched vs retired stream — critical distinction because of speculative prefetch and flushed branch targets), what it predicts, or how it resynchronizes on reset/illegal-instruction traps.
G5 — Monolithic scoreboard, undefined inputs major
Four anonymous arrows into uvm_scoreboard; no matching semantics (expected-vs-actual? bus-vs-retire?), and no group-level datapath visibility — yet the stated checking philosophy asks for scoreboards on major block groups (register file, ALU…) specifically to ease debug, but not per-module.
G6 — No program/stimulus architecture critical
Who builds the executed machine code? Where does the hex live? How is it loaded identically into instruction model, data model and RM shadow? How do directed vs random programs get selected per test? None of this exists in the baseline; the IF/LSU drivers' stimulus role (they are responders, shaping gnt/rvalid timing) is not stated, so "sequencer" semantics are ambiguous.
G7 — No end-of-test / pass-fail mechanism major
Nothing determines when a program finishes or what constitutes pass/fail (no ecall/ebreak semantics in scope; no CSR to read). A mailbox store convention + watchdog + drain/quiesce rule + check_phase reporting must be architected.
G8 — No reset architecture major
Reset owner, reset sequencing (before/while config), mid-run reset scenarios, monitor/scoreboard/RM behavior on reset (drop in-flight, resync), reset assertions and reset coverage are all absent.
G9 — Coverage sampling undefined minor
"Coverage (Subscriber)" — subscribed to what? Sampling fetched instructions would pollute coverage with speculatively-fetched, never-executed words (branch shadows). Committed-stream sampling must be the rule for ISA coverage; protocol coverage belongs to the interface monitors.
G10 — Missing engineering details layered around the core idea minor
No transaction class definitions, no agent configuration objects (delay distributions, outstanding limits), no timeout/watchdog, no logging/tracing conventions (disassembly for debug), no misaligned-split bus matching model, no outstanding/in-order enforcement rules for the slave drivers (P1–P3).

4. Proposed changes (baseline → proposal)

C1. Add the missing skeleton: tb_top module (clock gen, interface instances, DUT, binds), cv32e40p_base_test layer, cv32e40p_env, config_db conventions. (fixes G1)
C2. Specify the retire-observation path: cv32e40p_rvfi_if probe interface bound into cv32e40p_core (same non-intrusive precedent the RTL itself uses), with an explicit tapped-signal list and a formal rvfi_trans. (fixes G2)
C3. Merge the active/passive split: one active OBI slave agent per interface (if_agent, lsu_agent), each with sequencer + slave driver + one monitor publishing request-phase and completed-transaction items. The separate "passive agents with output monitors" are removed; passive behavior remains available via is_active config. (fixes G3)
C4. Fully specify ref_model as our own SV RV32IM ISS driven by the retired stream; define state, per-instruction step, predictions (rd value, next PC incl. trap redirect, memory effects), shadow memory, disassembler. (fixes G4)
C5. Keep one uvm_scoreboard but define it as three collaborating compare units under one roof (retire compare, LSU-bus matcher with misaligned reassembly, fetch-sanity), plus a separate small datapath_checker for register-file write-port/X0 checks (group-level debug visibility without per-module scoreboards). (fixes G5 + F3)
C6. Add the program path: program generator (SV source: directed suites + constrained-random streams emitting encoded RV32IM words) → program_loader → identical images into instr_mem_model, data_mem_model and RM shadow memory. Test selects program by name/seed. (fixes G6)
C7. Add end-of-test & time control: magic-address mailbox store (handled in lsu_agent data memory model) + retire watchdog in sys_ctrl_agent + drain rule + check_phase pass/fail. (fixes G7)
C8. Add reset architecture: reset policy in env_cfg, reset stretch/mid-run scenarios in sys_ctrl sequences, reset-aware monitors/RM/scoreboard (drop & resync), reset assertions and reset coverage. (fixes G8)
C9. Split coverage by source: ISA/scenario coverage on the committed stream (instr_coverage subscriber fed by rvfi_monitor); protocol coverage (delays, outstanding occupancy, back-to-back, misaligned pairs, byte-enable patterns) owned by the interface monitors. (fixes G9 + F4)
C10. Add the missing engineering layer: transaction catalog, agent cfg objects, watchdogs, log/disasm conventions, in-order/outstanding rules in slave drivers. (fixes G10)

6. Flows

6.1 Stimulus flow

  1. Test programs env_cfg (program name/seed, delays, reset policy) → env builds everything; program_loader materializes the image (generator run or +HEX $readmemh) and loads instr model, data model, RM shadow identically.
  2. sys_ctrl_agent sequence: assert reset ≥ policy cycles → apply static config + tie-offs → release reset → set fetch_enable_i=1.
  3. Core fetches from boot; if_agent slave driver answers (gnt/rvalid with configured delay distribution; ≤2 outstanding; in-order).
  4. Program executes: loads/stores answered by lsu_agent (data from model; byte/BE semantics; misaligned ops arrive as the legal two requests).
  5. Program termination: final store *0x2000_0000 = 1 → mailbox raises EOT → env drains (outstanding OBI = 0, retire idle) → check_phase.
  6. Optional phases a virtual sequence can inject at configured times: delay-profile switch (0-wait ↔ max backpressure), mid-run reset (reset policy), program-directed illegal-encoding blocks routed to mtvec stub then back.

6.2 Checking flow

  1. rvfi_monitor emits one rvfi_trans per committed instruction, in commit order.
  2. ref_model steps it → exp_trans (arch effects + next PC + mem effects + trap).
  3. uvm_scoreboard: (a) retire compare exp vs actual — pc chain, rd addr+data, mem op identity; (b) LSU bus matcher — each committed mem op ↔ observed data-OBI transaction(s), with misaligned reassembly (lowest addr first); (c) fetch sanity per §5.1. Anything out of reset queues is flushed on a reset event.
  4. datapath_checker gives RF-level isolation (which port/write/win) to turn "wrong rd at instr #N" into "RF port B arbitration / forward path" evidence immediately.
  5. sva_module continuously watches protocol/reset/invariant properties (sim fails at assertion time with exact signal context).
  6. Watchdog: no retire for N cycles (hang) → UVM_FATAL with last-PC context; global timeout backstop.

6.3 Coverage flow

  1. instr_coverage samples every committed rvfi_trans (never the fetched stream) → ISA/scenario covergroups per §5.1; reset events toggle scenario crosses.
  2. Interface monitors own protocol coverage: gnt/rvalid delay values, outstanding-level occupancy 0..2, back-to-back requests, misaligned split pairs, byte-enable patterns, redirect-fetch events.
  3. Report merge per seed; coverage closure assessed over the regression (per plan, updated later).

7. Assertion architecture

  • Location: sva_module bound into cv32e40p_top (baseline's correct choice — kept). Protocol properties may be implemented as interface-embedded assert modules for reuse, instantiated by the bind module — single ownership retained.
  • Groups: instr-OBI protocol (P1–P2), data-OBI protocol (P2–P3), reset invariants, first-fetch/boot address, tie-off quietness (no irq ack / no debug status change / no sleep since inputs are tied), pipeline invariants (writeback only after valid issue; x0 never written non-zero — duplicated cheaply in datapath_checker as data check), X-propagation guards post-reset.
  • Disable policy: all properties disable iff (!rst_ni); protocol assertions additionally hold during mid-run resets via the reset-event flush semantics.

8. Reset architecture

  • Driver: sys_ctrl_agent (reset polarities/lengths from env_cfg: initial long reset; optional mid-run shorts; deassert synchronous to clk).
  • Observers: sys_ctrl monitor records reset events (broadcast) → scoreboard flushes queues, RM re-enters init state (pc=boot), monitors drop partial transactions, coverage marks reset cross.
  • Checks: SVA (no req during reset; first fetch after release = boot_addr; quiet tie-offs), scenario coverage (reset-while-fetch-in-flight, reset-while-load-outstanding, reset during multi-cycle MUL/DIV).
  • After reset the same program flow re-executes (memory images are stable; mailbox store re-arms EOT).

9. Error / negative-test architecture

  • Illegal encodings (categories: undefined major opcodes; legal opcode + undefined funct3/funct7; reserved shift encodings) — produced by the program generator inside dedicated blocks; expected effect = fetch redirect to mtvec (checked via retire/PC chain; trap stub returns per program design). No CSR-side checks (out of goal).
  • Timing stress: worst-case gnt/rvalid delay combos incl. maximal outstanding occupancy, back-to-back bursts, delay profile switching mid-run.
  • Reset-while-busy: reset during outstanding transactions / multi-cycle ops (with resync semantics per §8).
  • Hang detection: retire watchdog + global timeout.
  • Explicitly excluded: OBI protocol-violation injection and OBI error responses — the core's OBI has no err/rid/rready, so legal slave behavior cannot include them; injecting master-side violations would test out-of-spec space. (Tool-side SVA still guards that our own driver never misbehaves.)

10. Configuration architecture

  • Single env_cfg at top; each agent receives a slim sub-cfg (delays, enables) — no duplicated knobs; is_active kept for agents (default ACTIVE) for possible reuse as pure monitors.
  • Memories/program: one loader, three identical sinks (single source of truth) + +HEX= override for bring-up with externally assembled code.
  • Register model: not built (CSR space is out of goal; nothing to model) — documented rejection, not an omission.
  • Virtual interfaces distributed via config_db from tb_top; rvfi probe interface reaches UVM side through config_db resource sharing after bind.

11. Debug & observability

  • Every rvfi_trans logs order#, pc, disasm, →effects; an immediate visual instruction trace.
  • scoreboard errors print both sides (expected from RM vs actual) + the last 5 retired instructions + outstanding bus state — failure localization at instruction granularity; often directly at the responsible stage via datapath_checker context.
  • Uniform verbosity IDs per component; +UVM_VERBOSITY + per-agent overrides; all monitors emit timestamped bus events at HIGH.
  • Wave anchors: rvfi probe interface instance sits inside the core hierarchy — signals pre-grouped for the waves view.

12. Scalability & reuse

  • Adding a test = new program sequence name; adding a timing scenario = new delay profile + virtual sequence — no TB edits.
  • If future scope turns on C/FPU/cust: instr_coverage/RM are table-driven at the opcode level (extend decode tables; add FPU agent off APU pins); OBI slaves, scoreboard skeleton, probes generically reusable. No speculative extra components are built now.
  • OBI slave agents are protocol-generic (usable on any OBI master DUT); only memory models + mailbox are DUT-specific.

13. Decision log (significant choices, with rejected alternatives)

D1 — Retire-level end-to-end checking is the primary check. The core is single-issue in-order; comparing every committed instruction's architectural effect against a golden SV ISS catches every datapath/control bug that matters to the goal. Rejected: per-stage instructional scoreboards (per philosophy: eases debug, not drowns it).
D2 — Pre-generated program in instruction memory (not a reactive fetch-time generator). Both are sanctioned; pre-generation gives reproducible program/seed pairs, trivial expected-behavior computation in the RM (it reads the same image), and clean coverage attribution (no feedback loop between coverage and stimulus). Reactive answering is retained only as driver delay shaping.
D3 — RM consumes the committed stream, not the fetched stream. Speculative prefetch + branch shadows make the fetched stream non-architectural. Committed-stream stepping keeps the ISS trivially in lockstep and makes flush semantics automatic (flushed words never reach the RM).
D4 — Hand-written SV ISS; no external ISS (Spike/whisper/OVP). Methodology constraint (build-everything-yourself) + dependency-free regressions. Cost is contained: RV32IM only (≈47 instruction forms), no CSRs/privileged state beyond trap-target PC.
D5 — Single scoreboard with three compare units + one small datapath_checker. Balances "not one monolith" vs "not per-module": all retire-vs-bus matching needs shared ordering context (natural home = one scoreboard); RF-port arbitration/x0 is a genuinely orthogonal concern with its own taps (small separate checker) — exactly the group-level debug aid requested.
D6 — One monitor per OBI interface; passive-agent duplicates removed. Eliminates two monitors on the same pins and the input/output ambiguity; passive behavior still available via is_active for any block-level reuse.
D7 — No per-module ALU/MUL/DIV scoreboards and no forwarding live-check. Those behaviors are fully observable at retire (RM computes the exact expected rd); stage-local duplicates would add maintenance without adding a single new bug found. Debug value is instead provided by granular expected-vs-actual messages + the RF-port checker + wave anchors. (Challenge-review tradeoff, explicitly recorded.)
D8 — EOT via mailbox store + watchdog; not ecall/ebreak. ecall/ebreak are out of required scope; a magic store address is standard, observable on the existing data port, and needs no core features.
D9 — ISA coverage on committed stream; protocol coverage in monitors. Avoids flush-pollution; keeps each coverage class next to the stream that owns its semantics.
D10 — v_sqr kept but deliberately thin. Today's coordination is modest (reset + delay-profile timing vs phases). Removing it would merge fine, but the cost of one handle + virtual sequences is small and pays off for reset/scenario tests and future features; documented so it does not accrete responsibilities.
D11 — No register model/RAL. CSR space is out of goal; RAL would be pure dead weight. Re-add if scope changes.
D12 — Bind-based RVFI probe instead of modifying RTL. Zero impact on the design under verification; identical to the RTL's own internal-verification technique; single maintenance point on RTL uprevs. Rejected: editing RTL to add an RVFI port (violates "don't touch the DUT"; risks mask bugs behind instrumented code).

15. Notes and limits of this proposal

  • The exact probe tap names in §5.2 are confirmed against the current RTL; if any internal net is renamed on an RTL update, cv32e40p_rvfi_if is the only file to adjust (flagged as the single fragility, mitigated by the RTL's own precedent).
  • The LSU bus matcher needs the exact split order/BE pattern, implemented from databook rules (lowest address first) and validated early against RTL with a directed misaligned smoke test.
  • Component names here are final for TB implementation, and the Verification Plan (separate task, untouched here) will be aligned to them afterwards — including renaming the plan-side references to the merged agents/monitors.
